## 一、连接层（172f6d2）

**问题**：空会话期 bootstrap 409（snapshot_missing）风暴——每秒重开租约，旧租约上的全部 timeline SSE 401 雪崩（HANDOFF 遗留痛点）。

- `RingingConnection.streamEvents`：404/409 会话未物化改为**保持租约** 1s 短退避重试（新 `bootstrapSnapshot`，对齐 Rust v2_stream 的 not-ready 短退避）。
- 续租连续 2 次失败**不再由 renewLoop 直接重开**（旧路径与主循环竞争出双租约），发 `_leaseExpired` 信号 → streamEvents 抛 LeaseExpired → `runWithBackoff` 唯一重连路径；SSE 同时监听租约轮换与服务端 EOF（EOF 原租约重订阅，不再换 client_session_id）。
- `connectOnce` 显式判定 epoch 变化并归零 canonical 游标；`ApiException.isSessionNotReady` 对齐 Rust error.rs（HTTP 404/409 **或** code 词表，attach 被拒时只有 code 可判）。
- **扫码配对闭环**：桌面 webui 已出 QR（`qaqh-pair` v1 payload），安卓 `PairingPayload` 解析逐字段兼容；`StoredCredentials` 新增 `scope`（device 身份标记）。
- **审批双身份分派**：device（扫码）→ `GET /approvals` challenge 快照驱动待审批列表（canonical id 不出 daemon，SSE 事件只作刷新触发器）+ 一次性 `POST /approvals/respond`；admin/手输 Direct → canonical 命令通道不变。ask 回答表单仍是遗留。
